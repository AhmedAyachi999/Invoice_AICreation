B. SOLVED (since Episode 7) - so you don't redo them
==================================================================================================
- Paid invoice not deletable: invoices.delete_invoice raises ValueError, check_command returns the message,
  api.remove_invoice -> HTTP 400.
- Router: chain of thought (Intention / To do that / So) + "Route: <word>"; route() parses only after "route:".
  "list unpaid invoices", "show the invoices of X" -> question. Modelfile-router rebuilt.
- Counting paid/unpaid: get_invoices has a status param ("paid"/"unpaid"), Python filters and returns a count;
  unknown status ("null") = all. New tool show_invoices: Python writes the list itself as the reply.
- Synonyms open/outstanding/pending = unpaid, settled/cleared = paid (SYSTEM in assistant.py).
- Example 8 removed (its fake ids INV-031/034, CUS-047 leaked into answers). SYSTEM ends with
  "The ids, names and numbers in the examples are made up."
- Name chooser: exact match first, then "contains" (Lamp vs Desk Lamp).
- Customers around Dortmund: Example 7 (bot filters a list itself); get_customers/get_products with args
  return a note "no filter, go through them yourself".
- Forms instead of free text (static/app.js): invoice chooser (sends bare id "INV-003"), Paid/Unpaid buttons,
  new customer form, new product form ("new product X, sell price A, buy price B"), product price edit form.
  router.py decides which form to show from the bot's question (result["ui"]).
- Negative price: router.py catches it before the bot and reopens the form with "A price can't be negative."
  (A Modelfile-product rule was tried and reverted: it broke other cases.)
- Turnover forms (per customer / per product) answered by Python: assistant.form_turnover, no bot (T1-T6 pass).
- Turnover with nothing selected = all: filter_id()/NO_FILTER in assistant.py ("", null, all ... -> no filter),
  product turnover gets a Python "Total" row, form message "turnover per customer from ... to ..., all customers".
