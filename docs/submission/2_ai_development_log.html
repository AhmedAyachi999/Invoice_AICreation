AI Invoice Assistant – AI development log

Claude Code (CLI) with Claude Opus · 7 of 12 episodes; full history in the git log

Working rule (CLAUDE.md): the agent shows each function and writes it only after the user's OK; tests and commits on request.

1 · First AI feature: customer chat (Ep. 2–3) modified

Task / contextA bot that creates, changes and deletes customers by chat; llama3.2:3b, "the chat never saves".
Agent's proposalText commands parsed by Python; all customer data sent to the bot so it could choose.
ToolsFile edits after approval, Python, Ollama, chat tests with the real bot.
Verification8 chat tests: 2/8.
OutcomeChanged: Python looks records up and decides, the bot only extracts the request → 7/8.
LessonThe small model must not hold data or make decisions – the basis of the whole design.

2 · Checker bots and prompt tuning (Ep. 3–4) rejected – failed

Task / contextMake the bot more reliable by letting a second bot judge or correct its answers.
Agent's proposalJudge and coach bots, a correction loop, spaCy name recognition, 21 tuning experiments by a sub-agent.
ToolsFile edits, a sub-agent, many bot runs, package install.
VerificationHold-out and fresh scenarios: the checker broke correct answers and invented placeholders; scores on known cases were too optimistic.
OutcomeRejected; only a simpler, general prompt was kept.
LessonAnother small model adds errors; checks belong in deterministic Python. Test on unseen wordings.

3 · Products and invoices by a specialised agent (Ep. 5) accepted

Task / contextBuild two more entities following the customer pattern.
Agent's proposalAn "entity-builder" agent description, then code, endpoints and bots for products and invoices.
ToolsA sub-agent with file and command access in the project.
VerificationEnd-to-end API test 30/30; bot weaknesses recorded as open problems.
OutcomeAccepted.
LessonA written-down method makes the agent fast and consistent – it also copies the method's weaknesses.

4 · One chat with forms (Ep. 7–8) modified

Task / contextOne chat for everything, turnover questions in plain English.
Agent's proposalA router bot, an assistant with tools, pickers in the website, Python guards against invented records.
ToolsFile edits incl. the website, bot runs, an acceptance-tester agent.
VerificationRepeated tests: the model copied ids wrong and dropped data in turnover answers.
OutcomeChanged: structured input goes through forms, and Python answers the turnover forms itself.
LessonWhere input can be structured, a form beats asking the model to extract it.

5 · Test scenarios by a test-writing agent (Ep. 10) accepted

Task / contextThe project's own scenario tests, 5 runs per scenario.
Agent's proposalA "test-writer" agent and one test script per group of scenarios.
ToolsMay write only in tests/ and run them – never changes the code under test.
VerificationFirst run: 12 failing scenarios, 7 after fixes.
OutcomeAccepted; remaining failures documented, bots not tuned to the test sentences.
LessonSeparating "who writes tests" from "who writes code" keeps the tests honest.

6 · Course requirements and evaluation (Ep. 11) accepted

Task / contextReplaceable local model, failure handling, health check, container, evaluation with a baseline.
Agent's proposalOpenAI-compatible API with configuration by environment, clear 503 errors, /health, a switch to run the bots without Python.
ToolsFile edits after approval, tests with the model server off, the evaluation script.
VerificationModel server down → 503, data unchanged; bot alone 12/20, bot + Python 20/20.
OutcomeAccepted.
LessonA baseline makes the value of the Python layer measurable – and must be rerun after every change.

7 · Code review before the submission partly accepted

Task / contextRead all code with the agent, remove dead code, fix design weaknesses.
Agent's proposalSeveral refactorings, incl. restricting the assistant to questions – predicted to break nothing.
ToolsFile edits after approval, full test runs, comparison with older commits, a separate test server.
VerificationAgainst the last commit, 4 scenarios got worse.
OutcomeThe refactorings were discarded and the tested version kept; two small router fixes were accepted after the user tested them.
LessonThe agent states predictions confidently; only tests against a known baseline show whether they hold.
