CLIENT
Web browser static/ · one chat · forms and pickers · Yes / No · Help · "AI" badge on model output
HTTP / JSON · 127.0.0.1:8000 (other programs: the same REST API)

API

/chat/helpCRUD /reports/health
documented with OpenAPI at /docs · errors 400 / 404 / 422 / 503
chat messages · CRUD and reports go straight to the domain (no AI)
SERVICES
Chat services (app/chat)
routerbot – change bots + guards assistant – toolsguide – RAG on user_guide.md
the AI understands and proposes · Python checks · nothing is saved by the chat

MODEL
SERVER
Ollama (outside the container, on the host) llama3.2:3b, temperature 0 – as inv-router-bot, inv-customer-bot, inv-product-bot, inv-invoice-bot (modelfiles/) and for the assistant and Help · nomic-embed-text for Help (RAG)
replaceable by any OpenAI-compatible server (e.g. LM Studio, llama.cpp) through the configuration

  • Service boundary: the container owns its database; other programs use only the REST API, never the database.
  • Without the model server the service still starts: tables, CRUD and reports work, /health says "degraded", the chat answers 503.
  • Numbers (CUS-, PRD-, INV-) and all arithmetic (totals, turnover) are done by Python, never by the AI.
